Why donor screening

Risk basis

In blood screening the assay result decides whether a unit is released for transfusion or destroyed.

That single fact sets test depth for every field in the pack. A value corrupted in migration is not a defect report, it is a patient-safety event — so the risk-based testing argument rests on consequence rather than on opinion.

No Glue crawler. Crawlers bill $0.44 per DPU-hour with a ten-minute minimum, and they infer schema rather than enforce it. Tables come from DDL derived from the mapping specification, so the catalogue is a controlled artefact rather than a scanner's guess.

Athena stands in for the client's warehouse. The reconciliation controls are ANSI SQL and port to Snowflake or Redshift unchanged. That substitution is a limitation of a zero-cost environment, and it is recorded in the configuration specification rather than left implicit.

Two findings from building it

Controls that were not controls

An IAM deny that never fires

The deployer policy restricted Lambda memory through a lambda:MemorySize condition key. That key does not exist — AWS never exposes memory in the authorisation context. Two further denies used invalid service prefixes. All three sat there looking like guard rails while matching nothing.

A negative test that could not fail

Denials were first tested by calling non-existent resources. S3 answers NoSuchBucket, which at the client is indistinguishable from a refusal, so the probe reported a pass on an inconclusive result. It was rewritten against the IAM policy simulator, which returns the authorisation decision itself and separates an explicit deny from an implicit one.
