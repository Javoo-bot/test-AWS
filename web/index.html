Where the data comes from

Fair first question, so it is answered before anything else.

Origin
Generated by a script in this repository. No real patient records, which is the normal constraint for showing this work outside a client engagement.
Modelled on
A donor screening laboratory. The assay panel is the marker set mandated for allogeneic donation screening under EU Directive 2002/98/EC — NAT and serology for HIV, HBV and HCV, plus syphilis and anti-HBc — carrying real LOINC codes.
Shape
What a fifteen-year-old system actually hands over: pipe-delimited flat files, Latin-1, local wall-clock timestamps with no offset column, numeric results as free text, and a control-total manifest.
Reproducible
Deterministic from a seed. Same seed, same 15,839 rows, same SHA-256 checksums.
Volume
500 donors · 1,204 donations · 13,735 screening results · 400 quality-control records.

What gets tested hard, and what does not

GAMP 5 two-stage scoring: severity × probability gives a risk class, then class × detectability gives priority. Testing everything to the same depth is not rigour, it is an absence of judgement.

Data elementSPDPriorityDriving concern
Screening result codeHiMdLoHIGHDecides unit release or destruction
Numeric result + unitHiMdLoHIGHA tenfold unit error is well-formed and passes every schema check
Donation identifierHiMdMdHIGHPrinted on the physical unit

Detectability does the real work here. Several defects are low-detectability by nature — they produce output that is well-formed, plausible and wrong. Those escalate to HIGH regardless of how unlikely they are.

Deliberately tested less: quality-control status is carried through verbatim and not recomputed. The recorded status is what the laboratory concluded at the time under the procedures then in force; recalculating it would replace a historical record with a present-day opinion. Disagreements are reported as findings, never silently corrected.

ALCOA+ applied to a migration

One principle dominates. Every other can be satisfied by a system that quietly improves data as it moves. Original is the one that forbids it.

The design rule throughout: a transformed value never replaces its source — it accompanies it.
What could have been lostWhat is retained instead
Local time replaced by UTCBoth, plus the resolved offset the source never recorded
Free-text results replaced by parsed numbersBoth — the source string is kept verbatim
<0.10 parsed as 0.10Numeric stays null; the comparator is kept separately. "Below detection" and "measured 0.10" are different assertions
Legacy assay code discarded once mappedAlways retained, mapped or not
Unit conversion buried in codeFactor recorded per record, so the arithmetic is auditable
Corrupt names silently repairedEvery repair carries the original and its source bytes. Speculative repairs are not applied at all
Rejected rows discardedEvery quarantined row keeps its complete source record

The audit trail deliberately records only decisions that altered, flagged or rejected a value — 24,773 entries. A trail containing every untouched field would run to hundreds of thousands, and noise is where real entries hide. A test asserts no no-op entry appears, so the rule holds by verification rather than intention.

What was produced

Executed against real AWS, not a simulation.

Specification
43 mapped fields, 14 rated critical. Consumed directly by the transform and the traceability matrix, so specification and code cannot silently disagree.
Traceability
13 requirements, 12 controls, all VERIFIED. Generated from runs that happened. Its first generation reported three requirements whose controls nothing exercised; those gaps were closed rather than edited out.
Evidence
24,773 audit entries · 17 requirement-tagged tests · installation qualification 23/23 on credential scope and 32/33 on configuration.
Open deviation
One check fails and is left failing: the alerting topic has no confirmed subscriber. Industry guidance is blunt about this — a report with zero deviations is a warning sign, not a clean result.
